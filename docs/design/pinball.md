# ピンボール実験

## 盤面と操作

- Spaceで左右を同時に操作する。ボール1個とバンパー6個で動きを確認し、得点・球数・終了条件は追加しない。
- ユーザー提示図を盤面形状の基準とする。左右端は上から下まで続く平行な縦壁で定義し、浅い弧の天井と、下部からフリッパーの支点へ向かう斜面を別の壁として接続する。中央の落下口を残す。
- 下部のガイドはベジェ曲線とし、終端の接線を休止中のフリッパーへ合わせる。終点は支点より6px上へ置き、太さ8pxのラインと丸い根元が滑らかにつながるようにする。描画と衝突は同じ曲線の点列を使う。
- ユーザー提示のワールドフリッパーのバトル画像に合わせ、外側の丸い根元から中央の細い丸先へ向かって上下の辺がほぼ直線で細くなる形とする。根元の半径約7px・先端の半径約3px・長さ90pxの輪郭を描画・衝突で共有し、右側は輪郭を反転して左右対称にする。
- 休止時は中央の先端が20度下がったV字、押すと先端が水平まで上がる。水平を越えて振ると接触面が外側を向くため、上げ過ぎない。
- 打球方向は球の接触位置に対応させる。提示図に合わせ、根元は鉛直から外側へ16度、長さの25%で真上、先端は中央側へ48度とし、左右で反転する。振り上げ面の角度だけで方向を決めず、接触位置から連続的に打ち分ける。外側の根元から中央の先端へ滑るほど中央へ打球が向く。目標位置へ自動追尾はしない。
- バンパーは提示図を基準に、上部左右・中央左右・下部の壁際へ2個ずつ置く。中央軸x=320に対し、各段の位置・高さ・半径を左右対称に揃える。上部は半径28px、中段と下段は24px。中央には球を通す空間を残す。形状変更前の配置比較値は現在の評価として使わない。
- ゲームと物理は真上から見た2Dとして扱う。擬似的な斜め視点はSubViewportのcanvas_transformで描画だけに掛け、球・枠・ミサイルで共有する。横倍率1.08、縦倍率1.0で画面中央を固定し、浅い斜め視点の縦横比と盤面の広さを両立させる。物理ノードは拡縮しない。
- 表示領域は640×360の16:9とし、盤面もこの座標範囲へ再配置する。縦方向だけを潰さず、球とフリッパーの寸法・速度を新しい高さに合わせる。物理ノードのscaleは1のままとする。床は24px間隔のチェック柄。選択されたモノトーン案に合わせ、暗いグレー2色の床・グレーの枠・ライトグレーのバンパーとフリッパーで構成する。枠は単色・太さ8pxのラインのみとし、バンパーは影・縁・キャップ・模様のない単色の円にする。フリッパーと目標も平面の塗りで描く。画面下部の操作説明は置かない。ミサイルとポストプロセスは既存の共通シーンを使い、ミサイルと目標の色は紫に揃える。
- 画面への拡大は最近傍とし、プロジェクト側のstretch倍率も含めて画面上の整数倍率を選ぶ。1280×720は2倍、1920×1080は3倍、2560×1440は4倍、3840×2160は6倍となる。整数倍で埋まらない部分は余白にし、640×360未満のウィンドウだけは全体が見える縮小を優先する。変更はピンボールのPreview内へ閉じ、プロジェクト全体の表示設定は変えない。
- 配色はstyles.gdのMONOCHROMEへまとめる。検討用の旧3案と数字キーによる切り替えは削除する。球の色・強度は独立したインスタンス設定のままとし、盤面の配色から上書きしない。
- ボールは左フリッパーの外寄りの上方から開始し、落下すると同じ位置へ戻る。中央の落下口から横にも高さにも距離を取り、復帰後に球を見て打ち返す余裕を作る。バンパー衝突時にミサイルを1発出し、上部中央の目標へ追尾させる。

## 衝突と反発

- 球の基本物理と描画は[共通ボール](ball.md)を使う。ピンボール側のBallはシーンとスクリプトを継承し、落下復帰とフリッパー・バンパーの特殊な応答を追加する。自動物理更新は止め、Tableが進める。
- RigidBody2Dの材質による反発と追加インパルスが重なり、フリッパーの回転で球をすり抜ける問題があったため、ボールをCharacterBody2Dの経路検査へ変更する。
- Tableがボールとフリッパーを最大1/240秒ずつ進める。プロジェクト全体の物理更新頻度は変更しない。フリッパーはStaticBody2Dを明示的に回転し、各刻みでforce_update_transformを呼んで衝突形状へ即時反映する。
- 球の移動にはmove_and_collideを使い、回転後の重なりも衝突として回復する。同じ刻み内で反射後の残り時間を進め、8回の接触でも解消できなければ残りの移動を破棄する。
- 受動的な反発は法線方向だけに適用する。打球可能な間だけ接触点の回転速度を含める。打球済みの振り上げでも回転速度を加えると、選んだ方向と速度が次の接触で上書きされるため、同じ押下では重ねて加速しない。速度上限は衝突応答後にも適用する。
- ピンボール側の球は重力630px/s²・速度上限600px/sとし、640×360の盤面に合わせる。共通ボールの設定を変更せず、継承したシーンで上書きする。プロジェクト全体の時間倍率は変更しない。
- 押下から100ms以内の有効な接触に、接触位置から求めた方向で550px/sの打球を出す。水平まで約35msで上がった後も短時間受け付け、少し早く押しても打ち返せるようにする。有効な打球で受付を消費し、離すと取り消す。押し続けた後、戻るとき、微小な接触には打球力を付けない。フリッパーの振り上げは10rad/s、戻りは7rad/sとする。
- バンパーは法線方向の最低離脱速度を480px/sへ補い、勢いよく反射させる。反発へ一定のインパルスを加算し続けない。衝突演出とミサイル発射は、接触面へ向かう速度が15px/sを超える接触だけを通知し、微小な静止接触で連続発射しない。
- 衝突で円の半径を12msで約12%膨らませ、110msで元へ戻す。中心は移動させず、大きくゆっくり伸縮する柔らかい印象を避ける。再衝突ではアニメーションを最初からやり直し、当たり判定の半径は固定する。
- 壁・フリッパーは描画と同じ座標・寸法を使う。滑らかな輪郭を保つため、これらの頂点はドットへ丸めず、4倍MSAAとラインのアンチエイリアスを使う。火花や軌跡はドットで描く。中央の落下口から抜ける動きは、障害物のすり抜けと区別する。
- 球は半径6pxとし、描画半径はCircleShape2Dから取得する。上面だけを持ち上げると球が埋まって見えるため、フリッパーの打球面は衝突輪郭に合わせる。球の影はフリッパーより先に描き、ずれを右2px・下4pxに抑える。
- BallのAppearanceにcolorとintensityを公開する。リニア色空間でRGBにintensityを掛け、球本体・軌跡・接触粒子へ使う。SubViewportはHDR 2Dで1を超える明るさを保持し、既存ポストプロセスへ渡す。球の設定を盤面から上書きしない。

## 打球ガイド

- [参考動画の5秒付近](https://www.youtube.com/watch?v=MyH9XMT7Qco&t=5s) をコマ送りで確認すると、約5.3〜5.7秒に右フリッパー上の球が外側から内側へ滑り、白い線が右上・ほぼ真上・左上へ連続的に変わる。この位置と方向の対応を打球と予測で共有する。扇状表示はユーザー指示により削除し、白い線のみとする。
- 白い線は、下降中の球に対し今押した場合の接触を最大1/240秒ずつ調べ、100msの受付時間内に当たる場合だけ描く。上昇中の球や押し続けているフリッパーには打球を予告しない。配置を変えても使えるよう、画面内の固定された高さでは表示を制限しない。
- 仮のフリッパー輪郭で接触を求め、実際の打球と同じ方向・速度の関数を使う。実物の球とフリッパーは移動しない。線は予測した接触位置ではなく現在の球の中心から、打球方向へ155pxの直線として描く。打球後の重力や反射を含む軌道は描かない。球の描画に使う端数の丸めも始点へ合わせ、画面上で離れないようにする。
- 線はTableのshow_shot_guideで表示を切り替えられる。盤面と同じ描画変換を使い、物理座標とのずれを避ける。

## 調整環境

- `table.tscn` をGodotの2Dエディタで編集する。移動・回転・複製・削除・グリッドスナップ・Inspector・Undo/Redo・シーン保存を標準機能へ任せる。専用の実行型編集シーンや配置用Resourceは持たない。確認時だけ通常の `preview.tscn` を実行する。
- 壁はPath2DとCurve2D、フリッパーとバンパーは実際の物理ノードとしてシーンへ保存する。実行時に配置を別データから上書きしない。各部品を `@tool` にして編集時も表示と衝突形状を更新し、ゲームと同じ形状を確認できるようにする。編集時にゲームの物理は進めない。
- 壁は標準のパス編集ハンドルで頂点とベジェの接線を操作する。同じサンプル点列を描画とカプセルの衝突形状に使う。衝突用ノードは内部生成し、シーンにはCurve2Dだけを保存する。床とTarget・球の開始位置は配置した壁から独立させる。
- 座標は640×360の物理座標で編集する。実行時だけSubViewportの描画変換と整数倍拡大を使う。標準の2Dグリッドスナップの間隔はユーザーが設定し、補助ボタンの間隔はTableのGrid Sizeから4／8／16pxを選ぶ。既存配置を読み込み時に丸めない。
- 標準機能にない補助だけをInspectorのツールボタンで追加する。各部品には位置のグリッド整列と対称側への反映、壁には制御点のグリッド整列、Tableには壁・曲線・バンパーの追加を用意する。エディタ全体のプラグインや追加ドックは作らず、補助操作をEditorUndoRedoManagerのシーン履歴に登録する。
- 対称反映はボタンを押した時だけx=320を軸に行い、個別編集を維持する。Mirror Pathで相手を指定し、未指定なら相手を追加する。天井のように自身へ対応する壁は、前半の頂点・接線から後半を揃え、壁を重複して作らない。曲線と衝突形状のResourceを共有して片側の変更がもう片側へ漏れることを避ける。
- フリッパーは長さ・休止角度・振上角度・往復の回転速度を持つ。長さを変更しても両端の丸みを維持し、接線でつないだ輪郭を描画と衝突で共有する。2Dエディタでの回転操作も休止角度へ反映する。
- 打球はInspectorのRoot／Middle／Tipで根元0%・中央50%・先端100%の角度と強度を指定し、区間ごとに線形補間する。左右で同じ外向き／中央向きの符号を使い、強度を球の基準打球速度へ掛けて速度上限を適用する。予測線も同じ関数を使う。初期角度は-16／16／48度、強度は全て1とする。選択中のフリッパーには3点の打球矢印と振上位置の破線を表示し、実行時にはこの編集補助を表示しない。

## 検証

- `experiments/pinball/tests/physics_test.gd` で30/60/120Hz、高速の壁衝突と減衰、異なる進入速度でのバンパーの離脱速度と通知回数、左右フリッパーの根元・中央・先端での回転接触、速度上限と落下復帰を検証する。打球方向に加え、鉛直550px/sの打球が0.9秒以内に頂点へ達し、225px以上の高さへ届くことを検証する。
- `tests/preview_test.gd` で内部解像度、代表的な4解像度の整数倍拡大、1366×768での余白、320×180での縮小、バンパーの左右対称と物理ノードのscaleを検証する。
- 実表示では、連続操作による打ち返し・盤面内の移動・バンパーからのミサイル発射と着弾を確認する。
- `tests/aim_test.gd` で左右・接触位置3通り・横速度3通りを検証し、予測と実際の打球方向の差が2度以内であること、予測が実物を動かさないこと、押し続けた状態と受付時間外の予測を表示しないことを確認する。左右の休止中のフリッパー上を実際に滑らせ、外向きから真上を通って中央向きへ線が連続的に変わることも検証する。
- `tests/layout_test.gd` では30/60/120Hzで反応操作・一定周期操作の6条件を各20秒検証する。現在の形状で枠外への漏れ・速度上限超過がないことを確認した。
- 実表示用の操作は `tests/playtest.gd` に置く。`tests/playtest_results.json` は縦壁・長いフリッパーへの変更前の配置比較で、現在の形状の測定値ではない。
- `tests/authoring_test.gd` でCurve2Dの変更と形状更新、標準シーン保存からの再読込、3点の角度・強度の補間と速度上限、配置変更後の予測と実際の打球の一致を検証する。グリッド整列・対称反映・部品追加の補助操作とUndo/Redoは実エディタで確認する。
