# ミサイル実験

- `preview.tscn` をF6で実行する。現行の横ずれ追尾＋不安定ミサイルを画面いっぱいに表示する。通常の `launcher.tscn` から `missile.tscn` を発射する。
- 描画解像度は640×360固定。Nearestで縦横比を保ってウィンドウ内へ拡大し、比率の違いは余白で埋める。操作説明は表示解像度で描く。
- 左ドラッグで目標を動かす。
- Spaceで追加発射、Rで同じ乱数列から再生、Mで目標自動移動、Pで停止、Sで0.25倍速、Tで軌跡線を切り替える。
- Cで狙い点・操舵方向の可視化を切り替える。初期状態はOFF。現行方式はエルミートを使用しない。
- 通常速度・自動発射で開始する。自動で停止やスローへ移行しない。

## 編集場所

- 現行ミサイルの設定は `missile.tscn` のMissileに集約する。`missile.gd` がNode2Dを直接継承し、飛行・横ずれ追尾・操舵誤差・命中・寿命を担当する。見た目は子ノードVisuals（visuals.gd）に分け、本体・排気・煙・軌跡・着弾演出をミサイルのシーン内で所有する。
- InspectorはFlight / Acceleration / Speed Control / Offset / Instability / Appearanceの同じ階層の6グループ。ミサイルには巡航速度上限・加速度・追尾・不安定さ・寿命を設定する。OffsetのMax Distanceは最大横ずれ量。Zero Distance（初期値0px）は横ずれが完全に0になる目標までの距離。Fade Distanceとの間で減衰し、Zero Distance以下では横ずれを加えない。滑らかに減衰させるにはZero DistanceをFade Distanceより小さくする。Power（0.1〜4、初期値2）は距離比に適用する指数で、1は線形、2は二乗。大きいほど接近時の横ずれが早く小さくなる。
- 発射数、発射角のばらつき、発射間隔は `launcher.tscn` で調整する。初期値は3発、Spread 45°、弾間隔0.12秒、斉射間隔3.2秒。採用ミサイルを設定済みで、発射時は位置・方向・目標・seed・初速を渡す。LauncherのFlightグループにはLaunch Speed（80px/s）、Tracking Delay（0.6秒）、Speed Ramp Time（0.45秒）を置く。Launcherが物理更新単位で追尾開始と希望速度を指示する。
- 排気・煙・着弾はVisuals/Particles（GPUParticles2D）。particles.gdshaderが移動・抵抗・重力・寿命、particle_pixels.gdshaderがピクセル形状・色・透明度・光彩を担当する。距離基準の発生処理と本体・軌跡線はvisuals.gdに残す。手動emit_particleを使うため、描画方式はForward Plus / Mobileを使用する。
- VisualsのShow Halo / Show Tracesで外観を調整する。ミサイル本体の色はルートのTintで指定する。飛行終了後も残る演出はミサイルから分離し、自分の寿命で消える。
- Arenaは目標・背景・比較表示を担当する。ミサイルの粒子や軌跡を生成・更新しない。
- 旧1〜3のシーン・スクリプトは `comparison/` に分離し、採用ミサイルから継承しない。検証用Launcherのみ旧エルミート引数と旧乱数消費順を維持する。通常のLauncherにはエルミート処理を残さない。
- 比較用1〜3の調整値は独立している。採用ミサイルの設定を変更しても旧方式へ自動反映しない。

## 追尾の可視化

- Cで実位置→狙い点→実目標を水色、狙い点を黄色、補正後の希望方向を桃色で表示する。将来軌道の予測線ではない。
- 生存中の最も古い弾を1発選ぶ。飛行終了後は次の弾へ切り替える。追尾開始前はLaunchと表示する。
- ミサイルの計算済み状態を読み出す。可視化で飛行や乱数列を変えない。
- Pによる停止中も目標をドラッグできる。狙い点と希望方向だけを更新し、位置・速度・寿命・不安定さの経過時間・乱数を進めない。

## 速度の調整

`missile.tscn` のSpeed Controlで追尾中の速度を調整する。直進中の発射速度には適用しない。

| 設定 | 初期値 | 意味 |
|---|---:|---|
| Turn Speed | 45% | 大きく旋回するときの、指示速度に対する割合。100%で無効 |
| Turn Angle | 90° | 旋回減速が最大になる、実速度方向と操舵方向の角度差 |

- 旋回角には操舵の不安定さも含む。実際の速度変化はAccelerationのLimit / Response Timeを通す。
- 進行方向が揃うと希望速度が戻り、再加速する。目標までの距離では速度を変えない。

## 操舵誤差

現行ミサイルは、休止と保持だけの周期で希望方向へ角度補正を加える。保持する角度の補間は行わず、実速度の変化は加速度制御に任せる。

| Instabilityの項目 | 初期値 | 意味 |
|---|---:|---|
| Enabled | ON | 希望方向へ角度補正を加える |
| Angle | 45° | 毎周期、-Angle〜+Angleから一様抽選する角度 |
| Hold Min / Max | 0.02 / 0.12秒 | 抽選角度を保持する時間の範囲 |
| Rest Min / Max | 0.03 / 0.20秒 | 補正0で休止する時間の範囲。初回も休止から始める |
| Fade In | 0.15秒 | 追尾開始から補正全体の影響を線形に増やす時間 |
| Capture Distance | 45px | 補正を弱め始める距離。Hit Radiusで0になるまで線形減衰 |

- 保持・休止時間と角度を周期ごとに抽選する。左右交互や最低角度を強制しない。
- 保持・休止のMin / Maxは大小を並べ替える。境界の余り時間を次の周期へ引き継ぐ。すべて0の周期では補正しない。
- 立ち上がり・復帰時間、補間切り替え、補間専用プレビューは持たない。Instabilityの内部名・設定名を統一する。
- 目標の更新や表示更新で周期をリセットしない。速度・加速度上限・追尾応答はランダム化しない。
- 比較用1〜3は旧処理を固定して残しており、現行ミサイルの設定変更や周期の簡略化は反映しない。

## 飛行と接近

- 採用ミサイルはSTRAIGHT / HOMINGの2状態。fly_straight(direction) / start_homing(target)で切り替え、desired_speedで希望速度を指示する。ミサイル内に追尾開始タイマーは持たない。
- LauncherはTracking Delay中にLaunch Speedを指示し、その後追尾を開始してSpeed Ramp Timeで希望速度をSpeedまで上げる。指示は物理更新単位で行う。直進中は目標なしでも飛行できる。
- 比較用の1・2のみ、毎物理更新、実位置と実速度方向を始点に、現在の目標まで単一エルミートを組み直す。Departure Lengthは固定長、終点接線長は現在距離×Arrival Scale。
- FrameがTarget RelativeならAngle / Spreadは現在の目標方向に対する角度。発射時に選んだ相対角を維持する。Worldならワールド基準の接近方向を保つ。
- 1・2はLookaheadで選んだ案内点、3は現在目標、4は横ずれした狙い点へ向く方向に操舵誤差を加える。加速度制限とResponse Timeを通し、実速度の平均によって位置を更新する。実位置へのノイズ加算や目標への吸着はしない。
- 全速度が加速度・巡航上限の対象。誤った操舵や急な目標移動によって減速し、向きが揃うと再加速する。
- 比較用エルミートの曲線は256分割。これは先読みのための内部数値計算で、形状を制約する演出パラメータではない。

## 検証

- `tests/speed_control_test.gd`: 距離によらない速度指示、旋回減速、外部指示、直進の維持と加速度上限を確認。

- `tests/launcher_test.gd`: 通常Launcherが採用シーンを生成し、エルミート引数なしで発射し、時刻に応じて追尾開始・巡航速度を指示できることを確認。

- `tests/instability_test.gd`: 周期時刻の物理FPS間の一致、保持中の角度が補間されないこと、ゼロ時間、乱数列の再現・独立性、強度0と通常の一致、強度の効き、回転に対する軌道の一致を確認。
- `tests/preview_test.gd`: 現行シーンと通常Launcherの参照、全画面配置、ドラッグ座標、再生時のseed、停止・スローの解除を確認。
- `tests/direct_test.gd`: エルミート設定を変えても直接追尾へ影響しないこと、現在目標の同期、エルミート版と同じ誤差の乱数列・時間変化を確認。
- `tests/offset_test.gd`: 距離比に対するPowerの適用、Zero Distanceの内外・境界・減衰区間なしの設定、目標方向を基準とする左右、両側の抽選、横ずれ0で直接追尾と一致すること、横ずれの有無が不安定さの乱数列へ影響しないことを確認。
- `tests/performance_test.gd`: 描画・粒子・可視化を除くCPU時間。瞬時の直接追尾・同じ加速度制御による直接追尾・現行方式を比較する。位置・速度と近距離から遠距離へ動く目標を各方式で揃え、100発／1000発を各100更新・9回計測する。ウォームアップ後に計測順を交代し、状態の再設定は計測に含めない。
- `tests/guidance_view_test.gd`: 表示ON／OFFでの軌道・速度・乱数列の一致、希望方向との一致、スナップショットの独立性、選択中の弾の終了・切り替え、停止中ドラッグによる狙い点更新とシミュレーション状態の維持を確認。
- 実行例: `godot --headless --path . --script res://experiments/missiles/tests/flight_test.gd`
- 初期値で検証した条件では全720軌道が着弾する。任意の設定・目標移動での命中を保証するものではない。

参考動画の観測資料は `reference/` に残す。`comparison/` は検証用の旧方式で、通常プレビューからは読み込まない。旧ルートシーンと補間比較プレビューは削除する。

## CPU計測

- 2026-10-29、Godot 4.7.2公式Windows版、headless。同じ位置・速度・移動目標で各100更新、9回の中央値。単位は1物理更新あたりのms。
- ミサイルの物理更新を直接呼ぶ。命中判定・寿命判定を含み、描画・煙・軌跡・生成・可視化・エンジンのノード更新配信を除く。状態の再設定は計測外。ウォームアップ後、方式の計測順を交代する。
- 現行設定：速度250px/s、加速度上限1200px/s²、応答0.02秒、旋回速度25%・角度50°、横ずれ120px・減衰180px・0到達40px・Power 2・直接狙い25%、不安定角50°・保持0.1〜0.2秒・休止0.05〜0.3秒・立ち上げ0.1秒・減衰開始100px。設定や環境を変えた場合は再計測する。

| 方式 | 100発 | 1000発 |
|---|---:|---:|
| 直接追尾・方向と速度を即座に変更 | 0.103 | 1.051 |
| 直接追尾・現行と同じ加速度制御 | 0.123 | 1.270 |
| 現行・横ずれ＋不安定さ＋旋回減速＋加速度制御 | 0.262 | 2.700 |

- 同じ加速度制御を使う直接追尾に対して現行は約2.1倍。差は100発で約0.14ms、1000発で約1.43ms／更新。最小構成の直接追尾に対しては約2.6倍。
- 実際のゲーム全体のFPSや描画込みの負荷比を示す値ではない。過去のエルミートとの比較値を現在の性能として引用しない。
- 実行例: `godot --headless --path . --script res://experiments/missiles/tests/performance_test.gd`

## GPU置換前の演出込み計測

- 2026-10-29、Godot 4.7.2、Forward Plus / D3D12、RTX 4070 SUPER、Editor接続のデバッグ実行。描画対象は640×360のSubViewport、表示ウィンドウ1447×813。物理60Hz、VSync無効、max_fps=0。空の状態でも表示側は約120FPS相当であり、フレーム間隔を純粋なCPU処理時間とは扱わない。
- `tests/render_performance.tscn` を実行する。各条件8秒、初期2.5秒を除いて測定。飛行中の発数を補充して維持し、終了後の煙・軌跡・着弾粒子、生成・解放も含む。起動直後から追尾させ、通常Launcherの直進猶予と速度ランプは使用しない。画面内の移動目標と分散した発射位置を使う。ゲーム本編・敵・背景・ポストエフェクトの負荷は含まない。
- 直接追尾にも同じ設定・加速度制御・Visualsを使う。速度や飛行時間が異なるため、粒子数・着弾頻度は方式間で一致しない。純粋な追尾処理の比較には前節のCPU計測を用いる。
- 物理CPUは早い優先順位の開始計測から遅い優先順位の終了計測まで。描画CPUはVisuals._drawを実行して描画コマンドを生成する時間の全ミサイル合計。GPUはSubViewportの描画時間。各列は個別の中央値であり、合計はフレーム時間の厳密な測定値ではない。

| 現行方式・飛行中の発数 | 物理CPU／更新 | 演出の描画コマンド生成CPU／描画 | GPU描画 |
|---|---:|---:|---:|
| 10 | 1.23ms | 1.01ms | 0.07ms |
| 30 | 2.80ms | 3.38ms | 0.11ms |
| 60 | 6.22ms | 8.41ms | 0.17ms |
| 100 | 11.96ms | 121.96ms | 0.25ms |

- 現行100発の演出なしは物理CPU約0.52ms。演出込みは計測終了時で約1.34万粒子、フレーム間隔中央値229ms、p95 242ms、描画25サンプル。100発の単純な直接追尾も物理CPU16.28ms・描画コマンド生成158.28msと重い。こちらは約1.55万粒子であり、現行方式との負荷差を追尾計算の差とは解釈しない。
- 60FPSの予算は16.67ms。数十発でも演出の負荷を考慮する必要があり、GPU置換前の実装のまま100発をゲーム本編へ組み込むことを軽い負荷とは評価しない。60発では物理と描画コマンド生成の中央値だけでも計約14.6msとなり、本編の処理余裕が小さい。高負荷時には物理の追いつき更新も発生するため、物理1更新の時間と実際のフレーム時間は一致しない。
- GPU時間に比べCPUの演出処理が大きく、まず演出の更新・描画方法を見直す対象とする。今回の測定だけで描画CPUが100発で急増する内部原因までは断定しない。Editor接続とデバッグ実行の影響があるため、製品版の性能保証には使わない。
- 置換前の生データは `tests/render_results.json`。最初の短いストレス試験は `tests/render_stress_results.json` に分ける。300・1000発は処理落ちにより描画サンプルがそれぞれ5・2しかなく、代表値としては採用しない。
- 計測用のrender_direct.gd / render_visuals.gdは本体の処理や設定を変更せず、比較と時間計測のみを担当する。通常のプレビューには組み込まない。

## GPU粒子への置換後

- 排気・煙・着弾粒子の寿命・抵抗・重力・移動・色・透明度・描画をGPUParticles2Dへ移した。1pxごとの排出、乱数順、火花1px・煙1〜3px、光彩、着弾36＋8粒、ワールド位置、本体と軌跡線を維持する。GPUとCPUの処理タイミングが異なるため、フレーム単位の完全な画像一致は保証しない。
- `visuals.tscn` のParticlesがGPU粒子を所有する。粒子ごとの寿命・経過時間・種類・サイズはCUSTOMで渡す。1024スロットを確保し、自動排出は無効、手動排出のみ。show_haloはインスタンス固有の描画Materialへ渡す。飛行終了時はGPU粒子を含むVisualsを残し、従来の1.2秒後に解放する。
- 同じ描画環境・設定・発数維持条件で100発を再計測した。各8秒、最初の2.5秒を除外。GPU置換後の描画CPUは、再描画が実行されたフレームだけを対象とする（再描画のないフレームの0を除く）。置換前の中央値には再描画のないフレームも含まれるため、厳密な同一統計ではない。100発の置換前は大きく処理落ちしており、各フレームで物理と再描画が実行されていた。

| 現行追尾100発 | 置換前 | GPU粒子へ置換後 |
|---|---:|---:|
| 物理CPU／更新 | 11.96ms | 1.56ms |
| Visualsの描画コマンド生成CPU／再描画 | 121.96ms | 3.15ms |
| SubViewportのGPU描画 | 0.25ms | 0.17ms |
| 実フレーム間隔中央値 | 229.19ms | 9.30ms |
| 実フレーム間隔p95 | 241.99ms | 15.63ms |

- 残るCPU処理は発生位置・乱数・排出、追尾、本体・軌跡線の描画、生成・解放など。置換後100発の演出なしは物理約0.80ms、同じGPU演出を持つ直接追尾100発は物理約2.36ms・描画コマンド生成約3.22msだった。個々の粒子数と飛行時間は方式間で一致しない。
- GPU粒子の生存数をCPUへ読み戻さず、結果のparticle_capacity_endは確保スロットの総数を記録する。置換前のparticles_end（実粒子数）と混同しない。置換後の生データは `tests/render_gpu_results.json`。
- 単体の命中・目標消失・演出の分離と解放、追尾の720条件、可視化による飛行・乱数への非干渉を確認した。実描画で粒子・着弾と停止を確認した。ヘッドレスの単体テストは発生要求を記録して検証し、GPUの動作確認を代替しない。
